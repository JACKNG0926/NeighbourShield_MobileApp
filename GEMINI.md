# Antigravity Mobile Rules: NeighbourShield (Flutter)

- **Repository Scope:** Flutter mobile client ONLY. The backend is an external Django REST API. Never invent API behavior, mock responses permanently, or alter contract schemas unilaterally.
- **Dart & Flutter SDK:** Dart SDK `>=3.5.0 <4.0.0`, Flutter 3.24+.
- **Tech Stack:**
  - Networking: `http` (`^1.2.0`). Strictly FORBIDDEN: `dio`, `chopper`, `retrofit`.
  - State Management: Native Flutter (`ChangeNotifier`, `ListenableBuilder`, `StatefulWidget`). Strictly FORBIDDEN: `flutter_bloc`, `riverpod`, `provider`, `get`.
  - Local Storage: `shared_preferences` (`^2.3.0`) for tokens and lightweight session flags.
  - Code Gen & Serialization: Manual immutable models with `fromJson`/`toJson`. If `build_runner` or `json_serializable`/`freezed` are added, keep strictly opt-in.
- **Directory & Architecture Pattern (Feature-First):**
  - `lib/app/`: Core app shell (`app.dart`), theme (`app_theme.dart`), and API endpoints (`api_config.dart`).
  - `lib/core/session/`: App-wide session state (`AppSession`) and role enums (`user_role.dart`).
  - `lib/features/<feature>/`: Feature slices containing:
    - `data/`: Repositories (`<feature>_repository.dart`) handling HTTP calls, auth headers, error parsing.
    - `models/`: Immutable domain models and DTOs with `fromJson`/`toJson`.
    - `presentation/pages/`: Screen-level widgets and page routing.
    - `presentation/widgets/`: Feature-scoped reusable UI components and sheets.
- **Canonical Reference Pattern:**
  - Reference: `lib/features/reports/` (`SafetyReport`, `SafetyReportRepository`, `CommunitySafetyReportsPage`).
  - Follow this structure for error decoding, `Authorization: Token <token>` headers, and state lifecycle.
- **Localhost API Routing Standard (`lib/app/api_config.dart`):**
  - Android Emulator: Route to `http://10.0.2.2:8000/api` (never `localhost` or `127.0.0.1`).
  - iOS Simulator / Desktop / Web: Route to `http://127.0.0.1:8000/api`.
  - Physical Device: Route to `http://<LAN_IP>:8000/api` (Django running on `0.0.0.0:8000`).
- **Serialization & Naming Mapping:**
  - Django API sends and expects `snake_case` JSON keys and ISO 8601 UTC date strings.
  - Dart fields MUST use `camelCase`. Map explicitly in `fromJson`/`toJson` (or `@JsonKey` / `FieldRename.snake` if code gen is added).
  - Fail closed on missing auth tokens or invalid backend roles; never grant unauthorized UI access.
  - Parse error responses by checking `detail` or extracting the first field validation error message.
- **Verification Commands:**
  - Static Analysis: `flutter analyze`
  - Unit/Widget Tests: `flutter test`
  - Dependency Check: `flutter pub get`
  - Code Generation (if configured): `dart run build_runner build --delete-conflicting-outputs`
